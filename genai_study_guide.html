Section 01
What is LangChain?
LangChain is a free, open-source Python framework that helps developers build powerful AI applications using Large Language Models (LLMs). It provides ready-made building blocks — Models, Prompts, Chains, Memory, Tools — so you can focus on what your app does instead of writing everything from scratch.
🌍 Real-Life Analogy – LEGO Set
Think of LangChain like a LEGO set for AI apps. LEGO gives you many different types of bricks that snap together perfectly. LangChain gives you ready-made components (Models, Prompts, Chains, Memory, Agents) that snap together to build anything — a customer support bot, a document analyser, a coding assistant, a travel planner.

Section 02
LangChain Components

LangChain is built from 6 core building blocks. Combine them in any order to build any AI application you can imagine.

① Models

The AI brain. Wraps LLMs (OpenAI, Anthropic, Gemini) with a unified interface. You call model.invoke() — LangChain handles the rest.

② Prompts

Dynamic templates with placeholders. Instead of hardcoding "Summarise Cricket", you write "Summarise {topic}" and fill it at runtime.

③ Chains

Pipelines that connect multiple steps. Prompt → LLM → Parser. Or Translate → Summarise → Format. All automated.

④ Memory

Gives the LLM the ability to remember previous messages in a conversation. Without this, every API call is brand new with no context.

⑤ Indexes

Connect your app to external data — PDFs, web pages, databases. Includes Document Loaders, Text Splitters, Embeddings, Vector Stores, Retrievers.

⑥ Agents

AI systems that can reason and decide which tools to use. Like a chatbot that can search Google, run code, query databases, and book flights.

Section 03
Models in LangChain
In LangChain, Models are the connectors to AI. There are 3 types: Language Models (text in, text out), Chat Models (messages in, message out), and Embedding Models (text in, vector/numbers out).
🗣️ Language Models (LLMs)

Give them any text, they continue or respond in text. Used for general text generation, translation, completion. Example: GPT-3, BLOOM.

💬 Chat Models

Optimised for conversations. They understand "system", "user", and "assistant" roles. This is what GPT-4, Claude, Gemini use. Modern standard.

📐 Embedding Models

Convert text into a long list of numbers (a vector) that captures the meaning of the text. Used in semantic search and RAG. Similar text → similar vectors.

Using Models — Code Examples

# OpenAI GPT-4 via LangChain
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()  # loads OPENAI_API_KEY from .env
model = ChatOpenAI(model='gpt-4', temperature=0)
result = model.invoke("What is LangChain?")
print(result.content)
# Google Gemini via LangChain
from langchain_google_genai import ChatGoogleGenerativeAI

model = ChatGoogleGenerativeAI(
    model='gemini-1.5-pro'
)
result = model.invoke("Explain RAG simply")
print(result.content)

⚙️ Temperature — Controlling Creativity

temperature is a number (usually 0 to 2) that controls how creative/random the model's output is. Low = predictable, High = creative.

Stories, Poems, Creative Writing0.9 – 1.2High creativity, varied output
Brainstorming, Wild Ideas1.5+Maximum randomness, very diverse outputs
🌍 Real-Life Analogy
Think of temperature like the creativity dial on a writer's desk. At 0, the writer writes only confirmed facts. At 1.5, they write wild science fiction. For a bank's FAQ chatbot → temperature 0. For an ad copywriter → temperature 1.0+.

Section 04
LLMs vs Chat Models — Deep Dive
Both are Language Models, but they are trained differently and used differently. LLMs (Base Models) just continue text. Chat Models are trained for back-and-forth conversation with role awareness.
FeatureBase LLMChat Model ✅ (Modern Standard)
What it doesContinues any text you give itHas a full conversation with you, understands context
Role AwarenessNone — no concept of "user" or "system"Understands "system", "user", "assistant" roles
MemoryNo built-in memory — statelessCan hold structured conversation history
TrainingTrained on raw internet textFine-tuned on human conversations + instructions
Best ForAutocomplete, translations, text generationChatbots, assistants, Q&A, agents
ExamplesGPT-3, LLaMA-2-7B, Mistral-7B (base)GPT-4, Claude-3, Gemini, LLaMA-2-Chat
🌍 Real-Life Analogy
A base LLM is like a very well-read author who, if you give them the start of a sentence, will complete it — but they don't know who you are or why you're asking.

A Chat Model is like a trained customer service agent. They know: "This is the customer (user). This is my job description (system). My last reply was... (AI message). What should I say next?" — full context awareness.

Section 05
Open-Source Models
Open-source models are AI models whose weights (the trained parameters) are publicly available. Anyone can download them, run them locally, fine-tune them on custom data, or deploy them on their own servers — for free, with no usage fees.
✅ Open-Source Models
  • Free to use — no API cost per token
  • Full control — you can modify and fine-tune
  • Data Privacy — runs on YOUR servers, data never leaves
  • Can deploy offline — works without internet
💳 Closed-Source Models (OpenAI, Anthropic)
  • Pay per API call (per token used)
  • No access to model weights — can't modify
  • Data is sent to their servers
  • Must use their API — no offline option

Section 06
Prompts
A prompt is the instruction or question you give to an AI model. The quality of the model's response depends almost entirely on how well you write your prompt. The skill of writing good prompts is called Prompt Engineering.
📝 Text Prompts

Plain instructions in text: "Summarise this article", "Translate to Hindi", "Write a poem about cricket".

🖼️ Multimodal Prompts

Prompts with images, audio, or video. E.g., "What is happening in this image?" used with GPT-4V, Gemini Vision.

3 Types of Prompts in LangChain

Type 1 — Dynamic Prompt (PromptTemplate)

A template with {placeholders} filled in at runtime. Write once, reuse for any input.

from langchain_core.prompts import PromptTemplate

# Define template with placeholders
prompt = PromptTemplate.from_template(
    "Summarise {topic} in a {tone} tone in {words} words."
)

# Fill in the values at runtime
filled = prompt.format(topic="Cricket", tone="fun", words="50")
print(filled)
# Output: "Summarise Cricket in a fun tone in 50 words."
Type 2 — Chat Prompt (ChatPromptTemplate)

Structured prompts for Chat Models with "system", "user", and "AI" roles. This is the modern standard.

from langchain_core.prompts import ChatPromptTemplate

chat_prompt = ChatPromptTemplate.from_messages([
    ("system", "You are an expert {profession}."),
    ("user", "Tell me about {topic}"),
])

messages = chat_prompt.format_messages(
    profession="Doctor",
    topic="Viral Fever"
)
Type 3 — Few-Shot Prompting (FewShotPromptTemplate)

You show the model a few examples of the desired pattern, then it applies the same pattern to new input. Like teaching by example.

examples = [
    {"input": "I was charged twice.",      "output": "Billing Issue"},
    {"input": "App crashes on login.",        "output": "Technical Problem"},
    {"input": "How do I upgrade my plan?",  "output": "General Inquiry"},
]
# Model now classifies any new customer ticket automatically!
🌍 Real-Life Example
This is how companies auto-classify thousands of support tickets. Show 3–4 examples → the LLM labels the next 10,000 correctly, without any training or retraining.
🎯
Section 07
Prompt Templates
A PromptTemplate is LangChain's way to create prompts that are dynamic, reusable, and validated. Instead of writing different prompts for each user, you define a template once with {variable} placeholders and fill them at runtime.
✅
Validates InputsAutomatically checks that all required variables are provided. Catches mistakes early.
♻️
ReusableDefine once, use across the entire app with different inputs.
🔗
ComposableChains perfectly with Models, Parsers, and other components using LCEL ( | operator).

Static vs Dynamic Prompts

🔒 Static Prompt (Hardcoded)

Same prompt every time. Cannot be reused for different inputs.

# Bad — hardcoded, not reusable
prompt = "Summarise the Attention paper in simple terms"
🔄 Dynamic Prompt (Template) ✅

Placeholders filled at runtime. Works for any paper, any style.

# Good — dynamic, reusable
prompt = "Summarise {paper} in {style} language"
# Call with: paper="Attention", style="simple"

Chat Prompt — Message Types

🔧 System Message
Sets the AI's persona and rules for the whole conversation. E.g. "You are a helpful doctor. Give simple medical advice only." The AI follows this throughout.
👤 Human Message
What the user types. E.g. "I have a headache and fever. What should I do?" This is the user's input in the conversation.
🤖 AI Message
The model's previous response. Used to maintain context in multi-turn conversations. Without this, the model forgets what it said.
MessagesPlaceholder — A special placeholder inside a ChatPromptTemplate that allows you to dynamically insert a list of chat messages (conversation history) at runtime. Essential for building chatbots with memory.

Section 08
Structured Output
By default, LLMs return free-form text. Structured Output forces the model to respond in a specific format like JSON — making it easy to use the data in your application, save it to a database, or display it in a UI.
❌ Without Structured Output (Hard to parse)

Response: "Here's a one-day Paris itinerary: Morning, visit the Eiffel Tower. Afternoon, explore the Louvre Museum. Evening, dinner on the Seine..."

→ Hard to display in a UI, hard to save to database, hard to process

✅ With Structured Output (Easy to use)
[
  {"time": "Morning",   "activity": "Eiffel Tower"},
  {"time": "Afternoon", "activity": "Louvre Museum"},
  {"time": "Evening",   "activity": "Seine dinner"}
]

→ Easy to display, save, filter, and process!

3 Ways to Get Structured Output

① with_structured_output()

Modern LLMs support this natively. Pass a Pydantic schema or TypedDict, and the model returns data in that exact format. No parsing needed!

② Output Parsers

For older models. The model returns text that looks like JSON, and the parser extracts and validates it for you.

③ Pydantic Models

Define Python classes with types. LangChain converts the LLM's output into typed, validated Python objects automatically.

Pydantic — Data Validation Library

Pydantic is a Python library that validates data types automatically. You define what shape your data should be (fields, types, constraints) and Pydantic enforces it. If the LLM returns wrong data, Pydantic catches the error.
TypedDictPydantic ✅JSON Schema
Type ValidationBasic (type hints only)Full, strict validationSchema-based validation
Default Values❌ No✅ Yes✅ Yes
Field Constraints❌ No✅ Yes (min, max, regex)✅ Yes
Use WhenSimple structures, trust LLMNeed strict validation & safetyNo extra library needed

Section 09
Output Parsers
Output Parsers take the raw text from an LLM and convert it into a clean, usable Python object. Think of them as a translator that converts messy LLM output into structured data your code can work with.
StrOutputParser

The simplest parser. Converts the model response into a plain Python string. Use this when you just need the text content.

from langchain_core.output_parsers import StrOutputParser
chain = prompt | model | StrOutputParser()
JsonOutputParser

Parses the LLM response as a JSON dictionary. Great for APIs that need structured data returned.

from langchain_core.output_parsers import JsonOutputParser
chain = prompt | model | JsonOutputParser()
PydanticOutputParser

The most powerful parser. Converts LLM output into a validated Pydantic object. Catches errors if the model returns wrong data.

from langchain_core.output_parsers import PydanticOutputParser
parser = PydanticOutputParser(pydantic_object=MyModel)
chain = prompt | model | parser
🌍 Real-Life Analogy
Output Parsers are like a hospital data entry clerk. A doctor writes notes in free-form text: "Patient is 35, has fever 102F, prescribed paracetamol." The clerk reads this and fills a structured form (Name, Age, Temperature, Medication). The parser does exactly this — turns messy LLM text into clean structured data.

Without Chain: Manually copy each article → get Hindi translation → paste into new prompt → get summary → repeat 1000 times!
With Chain: Input → Translate to Hindi → Summarise → Output — runs automatically for all 1000 articles at once!

Section 11
Runnables & LCEL
A Runnable is any LangChain component that follows a standard "unit of work" pattern: it takes input, does some processing, and returns output. Every component (prompts, models, parsers, retrievers) is a Runnable, so they all work together seamlessly.

The 3 Standard Methods Every Runnable Has

▶️
invoke(input)Run with one input synchronously. Most common. Returns result immediately.
📦
batch(inputs)Run on a list of inputs in parallel. More efficient than calling invoke() in a loop.
🌊
stream(input)Returns output word-by-word as it's generated. Enables the "typing" effect seen in ChatGPT.

2 Types of Runnables

Task-Specific Runnables

Core LangChain components that do a specific job: PromptTemplate (formats prompts), ChatModel (calls LLM), OutputParser (parses results), Retriever (fetches documents). All implement the Runnable interface.

Runnable Primitives

Building blocks for controlling how Runnables execute — in sequence, in parallel, conditionally. These are the tools for building complex pipelines.

Runnable Primitives — All 6 Explained

PrimitiveWhat It DoesReal-Life Analogy
RunnableSequenceRuns steps one after another using | operatorAssembly line — each station finishes before the next starts
RunnableParallelRuns multiple steps at the same timeA kitchen where chef, baker & barista work simultaneously
RunnableMapApplies the same step to multiple inputsA photocopier making multiple copies at once
RunnableBranchConditional routing — if X do A, else do BAirport check-in: domestic vs international counter
RunnableLambdaWraps any Python function as a RunnableHiring a freelancer to do a custom job in the pipeline
RunnablePassthroughPasses input unchanged to the next stepA transparent pipe — just moves data without touching it

LCEL — LangChain Expression Language

LCEL uses the | (pipe) operator to chain Runnables together. The output of the left side becomes the input of the right side — like Unix pipes but for AI pipelines.
# Classic LCEL chain — the modern way to build in LangChain
chain = prompt | model | output_parser

# One line instead of 3 separate calls:
result = chain.invoke({"topic": "Cricket", "tone": "fun"})

# LangChain automatically does this:
# step1 = prompt.invoke({"topic": "Cricket", "tone": "fun"})
# step2 = model.invoke(step1)
# result = output_parser.invoke(step2)
🌍 Analogy — Factory Assembly Line
LCEL is like a factory conveyor belt. Each Runnable is a machine (station) doing one job. The | operator is the belt that moves items between stations automatically. You don't manually carry products from station to station — it all flows automatically.

Section 12
Memory
LLM API calls are stateless — every call is completely independent. The model has NO memory of what you said before. LangChain's Memory component stores conversation history and automatically includes it in each new prompt so the model always has full context.
❌ WITHOUT Memory (Stateless API)
"Who is Narendra Modi?" → LLM → "He is the 14th PM of India"
"How old is he?" → LLM → "I don't have context about who 'he' is" ❌

Each call is completely fresh — no memory of the previous message.

✅ WITH Memory (Stateful)
"Who is Narendra Modi?" → LLM → "He is the 14th PM of India"
"How old is he?" → LLM + [history] → "He was born 17 Sep 1950, so he is 74" ✓

Memory injects previous turns — model always has full context.

Types of Memory

ConversationBufferMemory
Stores the FULL transcript of the entire conversation. Simple but grows large quickly and can hit the model's token limit for long chats.
ConversationBufferWindowMemory
Only keeps the last N messages (a sliding window). Prevents token overflow. Good for most chatbots.
Summariser-Based Memory
Automatically summarises older parts of the conversation into a short paragraph. Keeps memory compact for very long conversations.
Custom Memory
For advanced use cases — store specific facts, user preferences, or specialised state in a custom class.
🌍 Real-Life Analogy
Memory is like a call centre agent's notes. Without notes (stateless), every time you call back they have no idea who you are. With notes (memory), they say "Ah yes, last time you had a billing issue on Plan X — is that resolved?" Buffer Memory = keeping full call transcript. Window Memory = keeping only the last 5 calls. Summariser Memory = keeping a brief summary of all past interactions.

Section 13
RAG — Retrieval-Augmented Generation
RAG (Retrieval-Augmented Generation) is a technique where an LLM retrieves relevant documents from a knowledge base before generating its answer. This grounds the model's response in real, up-to-date data instead of just its training knowledge.

3 Benefits of RAG: (1) Use up-to-date information (2) Better data privacy — your data stays with you (3) No limit on document size
🌍 Real-Life Problem RAG Solves
Your company has 500-page HR policy documents. ChatGPT doesn't know your company's leave policy.
With RAG: Upload your PDFs → embed them → store in a vector DB. When an employee asks "What is the notice period?", the system retrieves the exact relevant pages and the LLM uses them to answer accurately. 100% grounded in your real documents.

Section 14
Document Loaders
Document Loaders are LangChain components that read data from various sources (PDF, text file, website, CSV, database) and convert them into a standard Document object format that can be used for chunking, embedding, retrieval, and generation.
📋 The Document Object Format

Every loader converts data into this standard format:

Document(
    page_content="The actual text content of the document...",
    metadata={"source": "filename.pdf", "page": 0}
)

page_content = the actual text. metadata = info about where the text came from (file name, page number, URL, etc.)

4 Main Document Loaders

📄 TextLoader

What it does: Reads plain .txt files and converts them into a LangChain Document.

Use Case: Chat logs, transcripts, scraped text, code snippets.

Limitation: Only works with .txt files — no PDF, no Word.

from langchain_community.document_loaders import TextLoader
loader = TextLoader("chat_history.txt")
docs = loader.load()
📑 PyPDFLoader

What it does: Reads PDF files. Each page becomes a separate Document object with page number in metadata.

Use Case: Loading textbooks, policy documents, research papers.

Limitation: Uses PyPDF library — not ideal for scanned PDFs or complex table layouts.

from langchain_community.document_loaders import PyPDFLoader
loader = PyPDFLoader("company_policy.pdf")
docs = loader.load()
# Returns: [Document(page=0,...), Document(page=1,...)]
🌐 WebBaseLoader

What it does: Downloads a web page and extracts its visible text using BeautifulSoup.

Use Case: Loading blog posts, news articles, static websites.

Limitation: Doesn't handle JavaScript-heavy pages (use SeleniumURLLoader for those).

from langchain_community.document_loaders import WebBaseLoader
loader = WebBaseLoader("https://en.wikipedia.org/wiki/Cricket")
docs = loader.load()
📊 CSVLoader

What it does: Reads CSV files into Document objects — by default, one row = one Document.

Use Case: Loading structured data like product catalogues, sales records, survey responses.

from langchain_community.document_loaders import CSVLoader
loader = CSVLoader("products.csv")
docs = loader.load()

DirectoryLoader — Load Multiple Files at Once

📁 DirectoryLoader

Loads ALL files from a folder at once using glob patterns. Very useful when you have many documents.

Glob PatternWhat It Loads
"**/*.txt"All .txt files in all subfolders (recursive)
"*.pdf"All .pdf files in the root directory only
"data/*.csv"All .csv files inside the data/ folder
"**/*"ALL files of any type in all subfolders

** means "search recursively through all subfolders"

load() vs lazy_load() — Which to Use?

✅ load() — Eager Loading
  • Loads ALL documents into memory immediately
  • Returns a Python list of Document objects
  • Use when: Small number of files, you want everything upfront
  • Risk: Can run out of memory with very large files
🔄 lazy_load() — Lazy Loading
  • Loads documents one at a time as you process them
  • Returns a Python generator (not a list)
  • Use when: Large documents or many files — saves memory
  • Best for: Streaming, chunking, embedding large datasets

Section 15
Text Splitting
Text Splitting is the process of breaking large documents (like 500-page PDFs) into smaller, manageable pieces called "chunks". LLMs have a maximum context length, and embedding models work better with smaller, focused text. Splitting solves both problems.
🌍 Why Split? — The Newspaper Analogy
A newspaper has 50 pages. If you ask a friend "Tell me about the sports section", you don't give them all 50 pages — you hand them just the sports pages. Text Splitting works the same way: it finds and extracts just the relevant chunks so the LLM only reads what matters. Smaller = faster + more accurate.

Why Text Splitting Matters

TaskWhy Splitting Helps
EmbeddingShort, focused chunks → more accurate and meaningful vectors
Semantic SearchSearch results point to focused info, not an entire chapter
SummarisationPrevents the model from mixing topics and hallucinating
Memory EfficiencySmaller chunks = less memory, faster processing, better parallelism

4 Types of Text Splitters

① Length-Based Splitting

How it works: Splits text every N characters (or N tokens), regardless of what the text says.

Key parameters:

  • chunk_size — max characters per chunk
  • chunk_overlap — how many characters to share between adjacent chunks (prevents losing context at boundaries)
from langchain.text_splitter import CharacterTextSplitter
splitter = CharacterTextSplitter(
    chunk_size=500, chunk_overlap=50
)
chunks = splitter.split_text(long_text)
Simple but crude — can split in the middle of a sentence.
② Text-Structure Based Splitting

How it works: Splits on natural language boundaries in this priority order:

  • \n\n — paragraphs (preferred)
  • \n — new lines
  • " " (space) — words
  • "" (empty) — characters (last resort)

This is RecursiveCharacterTextSplitter — the most recommended splitter for general use.

from langchain.text_splitter import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50
)
③ Document-Structure Based Splitting

How it works: Understands the structure of specific document types — Markdown headings, Python class definitions, HTML tags.

Examples:

  • MarkdownHeaderTextSplitter — splits at ##, ### headings
  • PythonCodeTextSplitter — splits at class and function boundaries
  • HTMLHeaderTextSplitter — splits at HTML header tags

Best when your document has clear logical sections (code files, documentation).

④ Semantic Meaning Based Splitting

How it works: Uses an embedding model to detect topic changes. When the semantic similarity between two adjacent sentences drops significantly, it creates a chunk boundary there.

Example: A document talking about "farming" for 3 paragraphs then switching to "cricket" — semantic splitter detects this topic shift and creates a new chunk at the boundary.

Most intelligent, but slower. Use when content quality matters most.

Section 16
Vector Stores
A Vector Store is a database designed to store and search through vectors (embeddings) very efficiently. When you embed your documents, you store those vectors here. When a user asks a question, you embed the question and find the most similar vectors in the store — those are your most relevant documents.
🌍 Real-Life Analogy — The Library Card Catalogue
Before computers, libraries had card catalogues — one index card per book, with keywords. To find books about "cricket", you look up "cricket" in the catalogue and it points you to the right shelves.

A Vector Store is a semantic card catalogue. Instead of exact keywords, it understands meaning. If you search for "batting technique", it also finds books about "batting stance", "shot selection", "run scoring" — because they're semantically similar.

Key Features of Vector Stores

💾 Storage
Stores vectors + associated text chunks + metadata. Can be in-memory or on-disk.
🔍 Similarity Search
Given a query vector, finds the K nearest stored vectors using cosine similarity or L2 distance.
📑 Indexing
Special data structures (ANN indexes) enable fast search over millions of vectors in milliseconds.
✏️ CRUD Ops
Add new vectors, update existing, delete old — manage the lifecycle of your vector data.

Vector Store vs Vector Database

Vector Store (e.g., FAISS)
  • Lightweight library for storing & searching vectors
  • No full database features (no transactions, no auth)
  • Ideal for prototyping and small-to-medium scale
  • You manage persistence (save/load manually)
  • Examples: FAISS, SimpleVectorStore
Vector Database (e.g., Pinecone, Qdrant)
  • Full database system — distributed, persistent, scalable
  • ACID transactions, backup/restore, authentication
  • Metadata filtering, concurrent access, horizontal scaling
  • Production-ready for large-scale apps
  • Examples: Pinecone, Qdrant, Milvus, Weaviate
💡 Rule of Thumb: For learning and prototyping → use FAISS (local, free). For production apps with millions of documents → use Pinecone or Qdrant.

Chroma Vector Store

ChromaDB is a lightweight, open-source vector database that's especially friendly for local development. It's the most commonly used vector store when learning LangChain.
Chroma DB Hierarchy

Chroma organises data like a real database:

Tenant (your app)
↓ has many
Databases
↓ has many
Collections (like tables)
↓ has many
Documents (chunks + vectors + metadata)
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings

# Create vector store from documents
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=OpenAIEmbeddings()
)
# Search for similar documents
results = vectorstore.similarity_search("What is the leave policy?", k=3)

Use Cases for Vector Stores

🔍 Semantic Search
Find documents by meaning, not just keyword match. "car" finds "automobile" results too.
📚 RAG Applications
Find relevant document chunks to give LLM as context before it answers.
🎬 Recommender Systems
Find movies/products similar to what user liked based on embedding similarity.
🖼️ Multimedia Search
Search images, audio, or video using their embedded representations.

Section 17
Retrievers
A Retriever in LangChain is a component that fetches relevant documents from a data source based on a user's query. It sits between the user's question and the LLM — its job is to find the most relevant pieces of information to give to the model. All retrievers in LangChain are Runnables.
🌍 Analogy — Research Assistant
A Retriever is like a research assistant in a library. You tell them what topic you're researching. They go to the shelves, pull out the 5 most relevant books, and hand them to you. You (the LLM) then read those books to answer the question — you don't read all 10,000 books in the library.

Types of Retrievers

1. Vector Store Retriever

The most common retriever. Converts your vector store into a retriever object. When you call it with a query, it performs semantic search and returns the top-K most similar documents.

# Convert vectorstore to retriever
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 3}  # Return top 3 docs
)
docs = retriever.invoke("What is the notice period?")
2. Wikipedia Retriever

Queries the Wikipedia API to fetch relevant articles for a given topic. Returns content as LangChain Document objects — no local data needed!

  1. You give it a query (e.g., "Albert Einstein")
  2. It sends the query to Wikipedia's API
  3. Wikipedia returns the most relevant articles
  4. They are returned as LangChain Document objects
from langchain_community.retrievers import WikipediaRetriever
retriever = WikipediaRetriever()
docs = retriever.invoke("Albert Einstein")
3. MMR Retriever (Maximal Marginal Relevance)

Problem with regular search: If you ask about "climate change", regular similarity search might return D1, D2, D3 — all about "Arctic glaciers melting". You get 3 nearly identical results!

MMR solves this: It picks results that are relevant to your query AND different from each other. So you'd get D1 (glaciers), D4 (wildfires), D5 (sea levels) — diverse but all relevant.

Regular Search (Bad)
1. D1: Arctic glaciers melting
2. D2: Arctic glaciers melting
3. D3: Deforestation in Amazon
MMR Search (Better) ✓
1. D1: Arctic glaciers melting
2. D4: Wildfires in California
3. D5: Sea levels in Mumbai & New York 
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 3, "fetch_k": 10}
)
4. Contextual Compression Retriever

Problem: A regular retriever returns entire document chunks — even if only 1 sentence is relevant to the query. This wastes the LLM's context window.

Solution: Contextual Compression Retriever retrieves documents AND then uses an LLM to compress each document — keeping ONLY the parts relevant to the query.

Example:
Query: "What is photosynthesis?"
Retrieved doc: "The Grand Canyon is famous. Photosynthesis is how plants convert light into energy. Many tourists visit."
After compression: "Photosynthesis is how plants convert light into energy." ✓

How It Works (Step by Step):

  1. Base Retriever (FAISS, Chroma) fetches N documents normally
  2. Compressor (usually an LLM) reads each document
  3. Compressor keeps only the parts relevant to the query
  4. Irrelevant content is discarded

Use when: Documents are long & mixed, you want to reduce context length, and you need to improve answer accuracy in RAG.

Tools in LangChain
A Tool is just a Python function (or API) packaged so the LLM can understand and call it when needed. Tools give the LLM superpowers — fetch live data, run code, call APIs, query databases.
✅ What LLMs CAN do
  • Reasoning — Think through a problem step by step
  • Language Generation — Write, translate, summarise, converse
❌ What LLMs CANNOT do (without Tools)
  • Access live data (weather, stock prices, news)
  • Do reliable maths — they hallucinate calculations!
  • Call external APIs or services
  • Run code or shell commands
  • Interact with a database
🌍 Analogy — Smart Intern
An LLM is like a brilliant intern who can write and reason perfectly, but cannot drive, make phone calls, or access the company database. Tools are like giving them a company phone, car keys, and database login. Now they can DO things, not just think about them.

Agent = Brain + Hands

🧠
LLM (Reasoning)

Thinks, plans, decides what to do next

🛠️
Tools (Action)

Actually does the work in the real world

2 Types of Tools

① Built-in Tools

Tools LangChain already provides — pre-built, production-ready, minimal setup. Just import and use.

Tool NameWhat It Does
DuckDuckGoSearchRunWeb search via DuckDuckGo
WikipediaQueryRunWikipedia summary lookup
PythonREPLToolRun raw Python code
ShellToolRun shell/terminal commands
RequestsGetToolMake HTTP GET requests to any API
GmailSendMessageToolSend emails via Gmail

② Custom Tools

You define them — wrap any Python function or API as a tool the LLM can call.

Use when:

  • You want to call your own APIs or microservices
  • You want to encapsulate business logic
  • You want the LLM to interact with your database or product

3 Ways to Create Custom Tools

① @tool Decorator

The simplest way. Add @tool above any Python function. LangChain reads the name and docstring automatically.

from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b
② StructuredTool + Pydantic

A Structured Tool where the input follows a Pydantic schema. Use when your tool needs multiple complex inputs with validation.

from langchain_core.tools import StructuredTool
from pydantic import BaseModel

class MulInput(BaseModel):
    a: int
    b: int

tool = StructuredTool.from_function(
    func=multiply, args_schema=MulInput
)
③ BaseTool Class

BaseTool is the abstract base class for ALL tools in LangChain. Both @tool and StructuredTool are built on top of it. Use for maximum control.

from langchain_core.tools import BaseTool

class MultiplyTool(BaseTool):
    name = "multiply"
    description = "Multiplies 2 numbers"
    def _run(self, a, b):
        return a * b

Toolkits — Bundles of Related Tools

A Toolkit is a collection of related tools packaged together for convenience and reusability. Import one toolkit to get all related tools automatically.
📦 Example: GoogleDriveToolKit
  • GoogleDriveCreateFileTool — Upload a file to Google Drive
  • GoogleDriveSearchTool — Search files by name or content
  • GoogleDriveReadFileTool — Read the contents of any file

Section 19
Tool Binding, Calling & Execution
To use tools with an LLM there are 3 steps: Bind (tell LLM which tools exist), Call (LLM decides which tool and arguments to use), and Execute (actually run the Python function and get a real result).
🔗 Step 1 — Tool Binding

Tool Binding registers tools with the LLM so it knows what tools exist, what each does, and what input format to use.

# Bind tools to the model
llm_with_tools = llm.bind_tools(
    [multiply, search_tool]
)
🌍 Analogy
Giving a new employee their access card and role manual. Before binding, LLM doesn't know tools exist.
📞 Step 2 — Tool Calling

Tool Calling is when the LLM decides it needs a tool and produces a structured response with the tool name + arguments.

Important: LLM does NOT run the tool — it only suggests which tool and arguments. LangChain/your code executes it.
{
  "tool": "multiply",
  "args": { "a": 8, "b": 7 }
}
⚙️ Step 3 — Tool Execution

Tool Execution is when the actual Python function runs using the LLM-suggested arguments.

# LLM said: call multiply(a=8, b=7)
result = multiply(a=8, b=7)
# result = 56  (real answer!)
🌍 Analogy
LLM is the manager writing the work order. Tool Execution is the employee who actually does the work.

AI Agents — Deep Dive
An AI Agent receives a high-level goal, then autonomously plans, decides, and executes a sequence of actions using external tools — while maintaining context, reasoning over multiple steps, and adapting to new information.

Formula: AGENT = LLM (brain) + TOOLS (hands)

5 Key Properties of an AI Agent

🎯
Goal-drivenYou tell WHAT you want, not HOW. The agent figures out the steps itself.
🔧
Autonomous PlanningBreaks down problems and sequences tasks without manual instruction per step.
🛠️
Tool-usingCalls APIs, calculators, search engines, databases to take real actions.
💬
Context-awareMaintains memory across steps — knows what it already discovered.
🔄
AdaptiveRethinks plan when things change — API fails, no results, tries another approach.

The ReAct Pattern (Reasoning + Acting)

ReAct is the design pattern used by most AI agents. The agent interleaves internal Thought with external Action in a loop until the task is complete. Introduced in paper "ReAct: Synergizing Reasoning and Acting in Language Models" (Yao et al., 2022).
💡 ReAct Trace Example
Thought: I need to find the capital of France.
Action: search_tool | Input: "capital of France"
Observation: Paris

Thought: Now I need the population of Paris.
Action: search_tool | Input: "population of Paris"
Observation: 2.1 million

Thought: I now know the final answer.
Final Answer: Paris is the capital of France with ~2.1 million people.

Agent vs AgentExecutor

🧠 Agent (Brain)

The reasoning component. Given query + scratchpad, decides: call a tool (AgentAction) OR return final answer (AgentFinish). Does NOT run tools itself.

⚙️ AgentExecutor (Manager)
  1. Sends query + scratchpad to Agent
  2. Gets AgentAction — executes that tool
  3. Collects observation, updates scratchpad
  4. Loops until Agent returns AgentFinish

Code — Creating an Agent

Step 1: Create Agent
from langchain.agents import create_react_agent
from langchain import hub

prompt = hub.pull("hwchase17/react")
agent = create_react_agent(
    llm=llm, tools=[search_tool], prompt=prompt
)
Step 2: Create AgentExecutor & Run
from langchain.agents import AgentExecutor

agent_executor = AgentExecutor(
    agent=agent, tools=[search_tool], verbose=True
)
result = agent_executor.invoke(
    {"input": "Capital of France?"}
)
print(result["output"])
💡 verbose=True prints every Thought, Action, Observation — great for learning and debugging!

Agents — Quick Reference
An AI Agent = LLM + Reasoning Capability + Tools. It's an AI system that can think about what to do, call real-world tools to get information or take actions, observe the results, and repeat until the task is complete — all autonomously.
🗣️ Normal Chatbot

Can only generate text. If you ask "What is the weather in Delhi right now?" → "I'm sorry, I don't have access to real-time data." ❌

🤖 AI Agent

Can call tools. "What is the weather in Delhi?" → calls Weather API → "It is 34°C and sunny in Delhi right now." ✅

🌍 Real-Life Example — Travel Booking Agent
User says: "Find me the cheapest flight to Shimla in January and book it."

The Agent thinks → calls Flight Search Tool → finds options → calls Price Comparison Tool → selects cheapest (₹2,450 on 24th Jan) → shows user for confirmation → calls Payment API → books the flight! All automatically.

Agent Architecture

User Request
→
LLM Reasons: "What tool do I need?"
→
Calls Tool (API, DB, Search)
→
Observes Result
→
Reason Again
→
Task Complete ✓

This Reason → Act → Observe loop repeats until the task is fully done. This is called the ReAct pattern.

Common Agent Tools

🔢 Calculator
Performs mathematical calculations. Avoids the model hallucinating maths answers.
🔍 Google Search
Searches the web for real-time, up-to-date information.
🗄️ SQL Tool
Queries your database with natural language — no SQL knowledge required from the user.
🌐 Wikipedia
Fetches Wikipedia articles as context for factual questions.
🐍 Python REPL
Executes Python code — useful for data analysis, file processing.
🛠️ Custom Tools
Any Python function you write can become a tool (call an API, send an email, etc.).

Project Setup Steps

  1. Create a project folder — Give it a meaningful name like my_langchain_app
  2. Open in VS Code — File → Open Folder → select your new folder
  3. Open the terminal in VS Code — View → Terminal (or Ctrl+`)

    Windows: venv\Scripts\Activate

  7. Install packages — pip install -r requirements.txt
  8. Create a .env file and add your API keys (see below)
  9. Verify installation — python -c "import langchain; print(langchain.__version__)"
